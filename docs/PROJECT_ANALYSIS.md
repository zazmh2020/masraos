# مسابقة الباركود — تحليل المشروع (Phase 0)

> نظام نقاط/خصم بالباركود لطلاب حلقات القرآن، سيُبنى **كوحدة داخل مسرى (MASRA)** بإعادة استخدام
> بنيتها القائمة. هذا المستند نتيجة STEP 1 — Project Discovery.

## 1. اكتشاف النظام الحالي
- المُسلَّم في `D:\مسابقة الباركود`: **`setup.exe` مُجمَّع (~8.8MB)** + دليل PDF (23 صفحة صُوَرية) +
  تصاميم بطاقات (PSD) + خط باركود **Code39** (`IDAutomationHC39M.ttf`) + أداة `doPDF`.
- **لا يوجد كود مصدري.** التطبيق القديم ويندوز مكتبي أحادي الجهاز. لذا «النسخة الجديدة» = **بناء جديد**
  مسترشد بالدليل، لا تطوير كود قائم.

## 2. قواعد العمل المستخرجة من الدليل (معتمَدة — مع وضع الغموض في OPEN_QUESTIONS)
- جهة خيرية واحدة لكل تثبيت؛ شعارها على البطاقات.
- **حلقات/فصول** ثم **طلاب**؛ لكل طالب **رقم ≥ 100** وباركود Code39 يشفّر الرقم، يُطبع على بطاقة.
- **المسح يمنح نقاطًا** بقيمة قابلة للضبط (10/20/30…؛ الأكبر مضاعف للأساس).
- **الخصم (F6):** خصم نقاط بمسح البطاقة أو إدخال الرقم.
- **شاشة العرض:** تعرض الطالب ورصيده/الخصم — مسح مباشر أو `F2` (يدوي)؛ `F4` خروج، `F6` خصم.
- **نسخ احتياطي:** نسخ/استعادة. **طباعة** البطاقات عبر doPDF.
- الدخول القديم: مستخدم `a` / كلمة `123` (ثابتة — تُستبدل بمصادقة مسرى).

## 3. خريطة إعادة الاستخدام (مسرى ↔ الباركود)
| مفهوم الباركود | في مسرى | القرار |
|---|---|---|
| الجهة الخيرية | `Organization` | **EXISTING** — إعادة استخدام |
| الطالب + رقمه | `Student.serial` (رقم تسلسلي) | **EXISTING** — الباركود = `serial` |
| الحلقة/الفصل | `Halaqa` | **EXISTING** |
| المصادقة/الأدوار | `auth` + `permissions` | **EXISTING** — بدل `a/123` |
| سجل النشاط | `AuditLog` | **EXISTING** — للعمليات الحسّاسة |
| قاعدة البيانات/النسخ | Postgres (Neon) — نسخ تلقائي مُدار | **EXISTING** — لا نظام نسخ مكتبي |
| **رصيد النقاط + الحركات** | — | **REQUIRED** — نموذج `PointsTransaction` (Ledger) |
| **إعداد نقاط المسح** | — | **REQUIRED** — حقل `pointsPerScan` على المؤسسة |
| **شاشة المسح / العرض** | — | **REQUIRED** — صفحتا `/scanner` و`/display` |
| بطاقة الطالب (باركود مطبوع) | نمط بطاقات الهوية `cards.ts` | **INFERRED** — توليد Code39 SVG للطالب |

## 4. المطلوب الجديد فعليًّا (حسب الدليل — بلا اختراع)
1. **Ledger للنقاط** — `PointsTransaction`: (student, org, kind: EARN/DEDUCT/ADJUST, amount,
   balanceAfter, reason, source: SCAN/MANUAL/REDEEM, `idempotencyKey`, createdBy, createdAt).
   الرصيد يُشتقّ/يُزامن من الحركات، لا حقل مفرد. كل تعديل يدوي = حركة `ADJUST` بسبب ومستخدم.
2. **حماية التكرار/Replay** — `@@unique` على `idempotencyKey` + معاملة DB ذرّية للمسح.
3. **إعداد `pointsPerScan`** لكل مؤسسة.
4. **API المسح** (خادمي، متحقّق من الصلاحية، ذرّي، مُدقَّق) + `/scanner` (إدخال يركّز على قارئ USB،
   F2 يدوي، F6 خصم) + `/display` (شاشة كبيرة).
5. **باركود Code39 (SVG)** لبطاقة الطالب — بلا مكتبة جديدة.
6. **تقارير**: مسحات/نقاط/سجل طالب (Backend: filter/aggregate/pagination).

## 5. المخاطر التقنية
- **سلامة النقاط** (الأهم): يجب Ledger + معاملات + Idempotency لمنع منح النقاط مرتين.
- عزل المستأجرين: كل حركة مرتبطة بـ`organizationId` (نمط مسرى القائم — آمن).
- المسح عبر قارئ USB = إدخال لوحة مفاتيح؛ يجب التحقق الخادمي لا الواجهة فقط.
- طباعة البطاقات: Code39 يحتاج توليدًا دقيقًا (checksum) — يُختبر بوحدة.

## 6. خطة التنفيذ (كوحدة مسرى — مراحل صغيرة قابلة للاختبار)
- **P1 — قاعدة البيانات:** `PointsTransaction` + `pointsPerScan` (هجرة إضافية آمنة) + دوال Ledger + اختبارات.
- **P2 — الصلاحيات:** قدرات `points.view/points.scan/points.adjust` في `permissions.ts`.
- **P3 — المسح والنقاط:** API المسح (idempotent/transactional/audited) + منطق الرصيد.
- **P4 — صفحة `/scanner`** (USB + F2 + F6).
- **P5 — شاشة `/display`.**
- **P6 — باركود Code39 + بطاقة الطالب القابلة للطباعة.**
- **P7 — التقارير** (سجل الطالب، المسحات، النقاط).
- **P8 — مراجعة أمنية + اختبارات قبول.**

بعد كل مرحلة: build + tests + فحص RTL/Responsive + رفع إلى GitHub، ثم تقرير قصير والتوقف.

## 7. أسئلة مفتوحة (OPEN_QUESTIONS)
- Q-001: هل الباركود = `Student.serial` مباشرة، أم رمز عشوائي منفصل (أأمن ضد التخمين)؟ **مقترح:** serial الآن (يطابق القديم)، مع إمكانية إضافة رمز لاحقًا.
- Q-002: هل «الخصم/الكوبونات» مجرد خصم نقاط (F6)، أم كتالوج خصومات؟ **الدليل:** خصم نقاط فقط.
- Q-003: هل تُطبع البطاقات كـPDF (كالقديم) أم عرض للطباعة من المتصفح؟ **مقترح:** طباعة المتصفح (أبسط).
