## 2. تنفيذ الترحيل على قاعدة الإنتاج الصحيحة

> الإنتاج وقواعد الاختبار كلها على `db.prisma.io` — **اسم المضيف وحده لا يكفي** للتأكد.

- [ ] انسخ رابط قاعدة الإنتاج من Prisma Console إلى متغير في الطرفية فقط (لا تلصقه في محادثة أو ملف داخل المشروع):

  ```powershell
  $env:DATABASE_URL = "<رابط قاعدة الإنتاج من Prisma Console>"
  ```

- [ ] **تحقق أنها قاعدة الإنتاج المقصودة:** شغّل

  ```bash
  npx prisma migrate status
  ```

  المتوقع: «24 migrations found» ثم قائمة «not yet been applied» تحوي **فقط** بعض أو كل الثلاثة الأخيرة بهذا الترتيب:
  `20261005100000_add_user_session_version` ← `20261006090000_add_org_ui_theme` ← `20261017100000_add_auth_throttles_and_password_reset`.
  (عطل الدخول الحالي سببه أن الأول غير مطبّق.) **توقف ولا تكمل** إن رأيت: ترحيلًا أقدم غير مطبّق، أو رسالة «The database schema is not empty» (P3005 — القاعدة أُنشئت بلا سجل ترحيلات وتحتاج baseline)، أو «drift»، أو ترحيلًا «failed».
- [ ] (اختياري، للقراءة فقط) اعرض الـ SQL الذي سيُطبَّق دون تنفيذه:

  ```bash
  npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script
  ```

  المتوقع: إضافة `sessionVersion` و`uiTheme` وإنشاء الجدولين فقط — لا `DROP` ولا `ALTER COLUMN`.
- [ ] طبّق الترحيل:

  ```bash
  npx prisma migrate deploy
  ```

- [ ] **تحقق:** أعد `npx prisma migrate status` ← «Database schema is up to date».
- [ ] احذف المتغير من الطرفية: `Remove-Item Env:DATABASE_URL`

> الترحيل يضيف جدولين فقط ولا يمس أي جدول أو بيانات قائمة، فالإصدار المنشور حاليًا يستمر بالعمل عليه دون تغيير.

## 3. متغيرات البيئة في Hostinger (قبل رفع الملف)

`NEXT_PUBLIC_*` تُدمج وقت البناء، لذلك اضبطها **قبل** رفع الملف وبنائه.

- [ ] `NEXT_PUBLIC_APP_DOMAIN=masraos.com`
- [ ] `NEXT_PUBLIC_APP_PATH_ROUTING=1` (موجود مسبقًا — تأكد فقط)
- [ ] `AUTH_SECRET`: موجود، عشوائي، 32 بايت أو أكثر. **لا تغيّره** (تغييره يسجّل خروج الجميع).
- [ ] `ENABLE_DEMO_LOGIN`: غير مضبوط أو فارغ.
- [ ] لا تضف `MASRA_SITE_ACCESS*` — بوابة الموقع ليست ضمن هذا الإصدار.

## 5. التحقق من الترويسات وعدم تعطّل الصفحات بسبب CSP

- [ ] من الطرفية:

  ```bash
  curl -sI https://masraos.com/
  ```

  المتوقع: `content-security-policy` يبدأ بـ `default-src 'self'` و**بدون** `unsafe-eval`، و`strict-transport-security: max-age=31536000`، و`x-frame-options: SAMEORIGIN`، وغياب `x-powered-by`.
- [ ] افتح أدوات المطور (F12) → Console، وتنقل في: الرئيسية، الباقات، التواصل، الدخول، التسجيل، ثم بعد الدخول: لوحة المركز، الطلاب، الحلقات، الحضور، الوثائق، المهام، المالية، التقارير، الإعدادات، المستخدمون، الرسائل، الإشعارات، ولوحة المالك.
- [ ] **تحقق:** لا رسالة «Refused to …» أو «Content Security Policy» في Console، ولا صفحة فارغة.
- [ ] جرّب حفظًا واحدًا على الأقل (مهمة جديدة مثلًا) للتأكد أن حارس الطلبات العابرة لا يمنع الطلبات من الموقع نفسه.

## 6. تسجيل الدخول وحماية المحاولات المتكررة

- [ ] سجّل دخولك بحسابك الحقيقي ← ينجح ويوجّهك للوحتك.
- [ ] **لا تختبر القفل على حساب حقيقي.** استخدم بريدًا غير موجود، ست مرات بكلمة خاطئة:
  - المتوقع: 5 مرات «البريد الإلكتروني أو كلمة المرور غير صحيحة»، والسادسة «محاولات كثيرة. حاول مرة أخرى بعد قليل.»
- [ ] **تحقق في سجل Hostinger:** لا توجد رسالة `auth_throttles unavailable … IN MEMORY`. وجودها يعني أن الجدول غير متاح (الترحيل لم يُطبَّق على هذه القاعدة) — الحماية تعمل حينها من الذاكرة، لكن عُد للخطوة 2.

## 7. استعادة كلمة المرور والبريد (Resend)

- [ ] في Resend: وثّق نطاق الإرسال (مثل `mail.masraos.com`) بسجلات DNS التي يطلبها.
- [ ] في Hostinger: `RESEND_API_KEY` (مفتاح بصلاحية إرسال فقط) و`EMAIL_FROM` مثل `MASRA <no-reply@mail.masraos.com>`، ثم أعد التشغيل.
- [ ] من صفحة الدخول → «نسيت كلمة المرور؟» → بريدك الحقيقي.
  - [ ] تصلك رسالة خلال دقيقة (افحص البريد غير المرغوب).
  - [ ] **الرابط يبدأ بـ `https://masraos.com/reset-password?token=`** (لا نطاق آخر).
  - [ ] عيّن كلمة مرور جديدة ← رسالة النجاح ← سجّل الدخول بها.
  - [ ] **الجلسات القديمة انتهت:** أي جهاز آخر كان مسجلًا يُطلب منه الدخول من جديد.
  - [ ] افتح الرابط نفسه مرة ثانية ← «رابط الاستعادة غير صالح أو منتهي الصلاحية».
- [ ] بريد غير مسجل ← نفس رسالة «إن كان البريد مسجلًا…» ولا تصل رسالة.
- [ ] إن لم تصل الرسالة: سجل Hostinger يحتوي `password reset email not sent (…)` مع السبب.

## 8. رفع الملفات إلى S3

- [ ] إعداد CORS في الـ bucket يسمح بـ `PUT` من `https://masraos.com` مع ترويسة `Content-Type`.
- [ ] من «الوثائق» ارفع:
  - [ ] ملف PDF صغير ← ينجح ويظهر في القائمة، والتنزيل يعمل.
  - [ ] صورة PNG أو JPG ← تنجح.
  - [ ] ملف بامتداد `.html` ← يُرفض قبل الرفع (نوع غير مسموح).
  - [ ] ملف HTML أُعيدت تسميته إلى `.pdf` ← يُرفض بعد الرفع: «محتوى الملف لا يطابق نوعه أو حجمه».
  - [ ] ملف أكبر من 25MB ← يُرفض.
- [ ] **إن فشل رفع PDF صالح** برسالة «تعذّر رفع الملف»: غالبًا المزوّد لا يقبل توقيع `content-length` أو CORS ناقص — أبلغني بالمزوّد (AWS/R2/غيره) ولا تتراجع عن بقية الإصدار لأجله.
