## 6. خطوات المالك — مطلوبة قبل النشر

### 6.1 ترتيب النشر (إلزامي)

1. **خذ نسخة احتياطية** من قاعدة الإنتاج (من Prisma Console) وتأكد أنها اكتملت.
2. **طبّق الترحيل على الإنتاج قبل رفع الكود:** من جهازك بعد ضبط `DATABASE_URL` على قاعدة الإنتاج:

   ```bash
   npx prisma migrate deploy
   ```

   الترحيل `20261017100000_add_auth_throttles_and_password_reset` ينشئ جدولين فقط. التراجع: حذف الجدولين.
3. **اضبط في Hostinger:** `NEXT_PUBLIC_APP_DOMAIN=masraos.com` (مطلوب لروابط الاستعادة). تأكد أن `AUTH_SECRET` قيمة عشوائية طويلة (32 بايت أو أكثر).
4. ارفع ملف التحديث، ثم جرّب: الدخول، صفحة «نسيت كلمة المرور»، ورفع وثيقة PDF.

> إن نُشر الكود قبل الترحيل: الدخول يعمل لكن **حماية التخمين متوقفة** ويظهر خطأ واضح في السجل، والاستعادة لا تعمل.

### 6.2 البريد

- الاستعادة جاهزة لمزوّد Resend الموجود. **لم يُختبر إرسال حقيقي.** للتفعيل: `RESEND_API_KEY` و`EMAIL_FROM` بنطاق موثّق، ثم تجربة على بريدك.
- بدون مزوّد: لا تُرسل رسائل، ويُسجَّل خطأ «password reset email not sent» (تحقق منه في بناء الإنتاج).

### 6.3 تخزين الوثائق (S3)

- بعد النشر جرّب رفع ملف PDF وصورة. إن رفض المزوّد الرفع بسبب الحجم الموقّع، أبلغني (توافق المزوّد مع توقيع content-length لم يُختبر على مخزن حقيقي).

### 6.4 النسخ الاحتياطي والبيئة التجريبية — REQUIRES INFRASTRUCTURE ACCESS

| البند | الحالة | المطلوب منك |
|---|---|---|
| نسخ احتياطي للإنتاج | غير موجود في المستودع (`Backup-MASRA.cmd` محلي فقط) | فعّل النسخ اليومي في Prisma Console، وجرّب استعادة نسخة إلى قاعدة منفصلة مرة واحدة |
| بيئة Staging | غير موجودة | قاعدة منفصلة + تطبيق منفصل في Hostinger (أو نطاق فرعي) يُنشر عليه كل تحديث أولًا |
| النشر الآلي | يدوي ZIP | (لاحقًا، بموافقتك) نشر من GitHub بموافقة يدوية للإنتاج |
| مراقبة الأخطاء | `ERROR_WEBHOOK_URL` اختياري | اضبطه على قناة Slack/Discord لتصلك أخطاء الإنتاج والتنبيهات الأمنية |

### 6.5 حساب GitHub — يدويًا

- التحقق بخطوتين على حسابك، ومراجعة المشاركين وصلاحياتهم (أقل صلاحية لازمة).
- من Settings → Code security: تفعيل Secret scanning وDependabot alerts وCodeQL.
- حماية الفرع `main`: منع الدفع المباشر واشتراط نجاح فحص CI.
