# مراجعة الإصلاحات الأمنية المتبقية

14 أكتوبر 2026. اعتمد المستخدم منع دخول التطوير في الإنتاج وإصلاح تزامن التحقق وإعادة الإرسال؛ نُفذا في النسخة المحلية. بقية البنود أدناه خطة مراجعة وليست إعلان جاهزية أمنية.

## إصلاحات موضعية منجزة

- صندوق إشعارات المؤسسة يستعلم وفق صلاحيات الفاعل؛ لا يجلب بيانات الطلاب أو المتبرعين أو المستخدمين إلى عضو لا يملك صلاحيتها.
- طلبات العضو في الإشعارات مقيدة بمعرّف صاحب الطلب، وفق سياسة شاشة الطلبات القائمة.
- موقع المؤسسة العام يعرض الإعلانات المنشورة فقط؛ بيانات SEO للجهة غير المنشورة لا تُفهرس.
- ملخص ولي الأمر يقيد علاقة الأبناء بالمؤسسة، والسجلات الزمنية للطالب مقيدة بالمؤسسة.
- اختبارات حية نجحت لرفض الطالب من مؤسسة أخرى، وتعديل استمارته من مؤسسة أخرى، وصلاحيات ولي الأمر، وحماية الجلسة التجريبية الموقعة، وعدم كشف الإعلان غير المنشور.
- dev-login يرفض الإنتاج قبل أي استعلام مستخدم أو إنشاء جلسة، حتى مع ENABLE_DEMO_LOGIN=1. مسار العرض العام المنفصل ما زال يثبت حساب العرض ويضع علامة القراءة فقط.
- verify/resend يستخدمان قفل صف PostgreSQL مشتركًا داخل معاملة؛ قراءة الحالة والصلاحية والحدود تحدث بعد القفل، واستهلاك الطلب وإنشاء المركز ومديره ينجحان معًا أو يتراجعان معًا.
- إعادة الإرسال تحجز الميزانية وتبطل الرمز القديم وتعيد المحاولات قبل الاتصال بالمزوّد خارج المعاملة. عند الفشل أو الاستثناء لا يُستعاد الرمز القديم ولا تُسترد ميزانية الإرسال، وتظل مهلة 60 ثانية سارية؛ فقد تصل رسالة رغم فشل تأكيد المزوّد. الرمز المحجوز يبقى صالحًا إن وصل، إلى انتهاء صلاحيته أو استبداله. يرفض الإرسال التالي عند بلوغ الحد ويطلب بدء التسجيل من جديد.
- اجتازت اختبارات قاعدة البيانات المعزولة التزامن، انتهاء الصلاحية أثناء انتظار القفل، الاستعمال الواحد، الحد الأقصى للإرسال، فشل المزوّد، وإرجاع استهلاك الطلب عند تعارض إنشاء المؤسسة. لم يتغير مخطط البيانات أو حدوده القائمة: 5 محاولات لكل رمز، 5 إرساليات لكل طلب، و10 دقائق صلاحية.

## تغييرات تحتاج مراجعة مستقلة قبل التفعيل

| الأولوية | المشكلة المثبتة في المصدر | الإصلاح المقترح | اختبارات القبول |
|---|---|---|---|
| High | login لا يطبق محدد محاولات في مساره | تقييد موزع بالمستخدم والمصدر مع رسائل متسقة؛ اختيار تخزين ونطاق وعمر المحاولات | محاولات متزامنة، انتهاء النافذة، سياسة الوكيل الموثوق، وعدم كشف وجود البريد |
| Medium | سياسة رؤية المعلم في التعليم أوسع من حلقاته في بعض صفحات الموظفين | اعتماد مصفوفة المنتج للدور والمساعد والإشعارات قبل تشديد المجال داخل المؤسسة | معلم في حلقة أ ومعلم في ب، دور مخصص، واجهة/API/تصدير/مساعد |
| Medium | استعادة كلمة المرور ومزود الإرسال الحي غير جاهزين للتحقق في البيئة الحالية | اعتماد قناة تحقق ومواصفات الرموز والإبطال ثم التنفيذ منفصلًا | حساب غير موجود، انتهاء رمز، استعمال مرة واحدة، إنهاء الجلسات القديمة |
| Medium | لم يُنفذ تدقيق شامل لكل عائلات API وCSRF ورفع الملفات والتكاملات | تدقيق مرحلي بالمصفوفة المرفقة وبيئة خدمات اختبار | اختبارات سالبة لكل مورد، الأصل والكوكي، نوع/حجم الملف، عدم تسريب الأسرار |

لا تتطلب التحسينات المحلية الجديدة تغيير مخطط بيانات أو مفاتيح الإنتاج. قبل أي تغيير مصادقة كبير: لقطة مصدر وقاعدة اختبار، اختبارات مستقلة، مراجعة أثر الدخول، وخطة رجوع لا تعيد ثغرة سابقة.

## أدلة الإصلاحين المعتمدين

- `auth-unit-tests.json`: 189 اختبارًا ناجحًا؛ خمسة اختبارات جديدة لمنع الإنتاج وحفظ دخول التطوير والعرض العام المحدد.
- `auth-concurrency-tests.json`: 11 اختبارًا ناجحًا ضد PostgreSQL الحقيقي في قاعدة المعاينة المعزولة، مع محاكاة التسليم وإصدار الجلسة. بيانات الاختبارات مؤقتة وتُحذف بعد كل حالة.
- `production-login-qa.json`: 18 فحص HTTP على بناء الإنتاج، لستة حسابات مع العلم غير مضبوط و0 و1؛ كلها 404 بلا كوكي جلسة. أُغلقت الخوادم المؤقتة بعد الفحص.
- `security-and-signup-qa.json`: أُعيدت الفحوص الحية الأربعة عشر، بما فيها التسجيل الكامل والعزل وحماية جلسة العرض من التعديل، ونجحت.
- `auth-build-log.txt`: بناء الإنتاج وفحص الأنواع ناجحان؛ فحص ESLint خالٍ من الأخطاء والتحذيرات.

لإعادة اختبارات التزامن محليًا: `node node_modules/vitest/vitest.mjs run --config vitest.auth.config.ts`. ترفض الاختبارات أي قاعدة غير المعاينة المحلية المحددة. لفحص الإنتاج بعد البناء: `node scripts/production-login-qa.mjs`؛ يشغّل خوادم مؤقتة على منافذ محلية حرة ويوقفها تلقائيًا. لم يُختبر مزوّد إرسال خارجي فعلي.
